# DDL Lock Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Block accidental DDL (e.g. an app migration) on the old and new clusters during the upgrade window, since logical replication does not carry DDL and a stray schema change would break apply.

**Architecture:** A PostgreSQL **event trigger** on `ddl_command_start` raises an exception unless the session has the bypass GUC `pg_upgrade.allow_ddl = on`. The tool's own connections always carry that GUC (set as a pgx startup `RuntimeParam`), so the tool's legitimate DDL passes while un-bypassed app DDL is rejected. The lock is installed in `prepare` (on the old primary), re-asserted idempotently in `catchup` (on the new PG17 leader, which also inherits it via physical replication + pg_upgrade), and released in `finalize`.

**Tech Stack:** Go, pgx/v5 + pgxpool, pgxmock for unit tests, the existing `internal/clients/pg` + `internal/phases` packages.

This is Plan 1 of the shadow-cluster upgrade design (`docs/superpowers/specs/2026-06-15-shadow-cluster-upgrade-design.md`). It is self-contained and also improves the current (cannibalize-N1) tool.

```go
// LockDDL installs an event trigger that rejects any DDL whose session does not
// set pg_upgrade.allow_ddl = on. The tool's own connections carry that GUC (see
// NewFromDSN), so its DDL passes; an accidental app migration is rejected.
// Idempotent: re-running replaces the function and recreates the trigger.
func (c *internalClient) LockDDL(ctx context.Context) error {
	_, err := c.q.Exec(ctx, `
		CREATE OR REPLACE FUNCTION pg_upgrade_block_ddl() RETURNS event_trigger AS $$
		BEGIN
			IF current_setting('pg_upgrade.allow_ddl', true) IS DISTINCT FROM 'on' THEN
				RAISE EXCEPTION 'DDL is locked during the online upgrade (command %)', tg_tag
					USING HINT = 'pg-upgrade safeguard: an app migration must not run now.';
			END IF;
		END;
		$$ LANGUAGE plpgsql;
		DROP EVENT TRIGGER IF EXISTS pg_upgrade_ddl_lock;
		CREATE EVENT TRIGGER pg_upgrade_ddl_lock ON ddl_command_start
			EXECUTE FUNCTION pg_upgrade_block_ddl();
	`)
	return err
}

// UnlockDDL removes the DDL lock so normal schema changes resume.
func (c *internalClient) UnlockDDL(ctx context.Context) error {
	_, err := c.q.Exec(ctx, `
		DROP EVENT TRIGGER IF EXISTS pg_upgrade_ddl_lock;
		DROP FUNCTION IF EXISTS pg_upgrade_block_ddl();
	`)
	return err
}
```

```go
// BypassDDLConfig parses dsn and marks the connection so it is exempt from the
// DDL lock (see internalClient.LockDDL): every connection started from this
// config sends pg_upgrade.allow_ddl=on in its startup packet, so the event
// trigger lets the tool's own DDL through.
func BypassDDLConfig(dsn string) (*pgxpool.Config, error) {
	cfg, err := pgxpool.ParseConfig(dsn)
	if err != nil {
		return nil, fmt.Errorf("pg parse dsn: %w", err)
	}
	if cfg.ConnConfig.RuntimeParams == nil {
		cfg.ConnConfig.RuntimeParams = map[string]string{}
	}
	cfg.ConnConfig.RuntimeParams["pg_upgrade.allow_ddl"] = "on"
	return cfg, nil
}

func NewFromDSN(ctx context.Context, dsn string) (*PoolClient, error) {
	cfg, err := BypassDDLConfig(dsn)
	if err != nil {
		return nil, err
	}
	pool, err := pgxpool.NewWithConfig(ctx, cfg)
	if err != nil {
		return nil, fmt.Errorf("pg connect: %w", err)
	}
	return &PoolClient{pool: pool}, nil
}
```

## Notes for the implementer

- **Idempotency depends on the bypass (Task 2).** On a live server, re-running `LockDDL` runs `CREATE OR REPLACE FUNCTION` and `DROP EVENT TRIGGER` *while the trigger exists* — those are themselves DDL and would be blocked, except the tool's connection carries `pg_upgrade.allow_ddl=on`. Unit tests (pgxmock) don't enforce triggers, so they pass regardless; the bypass is what makes it correct against PostgreSQL.
- **What's DDL vs not:** the event trigger fires on `ddl_command_start`. Sequence sync (`setval()`) and the logical-apply worker (row DML) are not DDL and are unaffected. The tool's `FreezeForUpgrade` (`CREATE TRIGGER`), `DropPublication`, `CreateSubscription`, `DisableSubscription`, `DropSubscription` ARE DDL and rely on the Task 2 bypass — which is global to the tool's connections, so no per-method change is needed.
- **Old cluster unlock:** not done here. The old cluster stays DML-frozen and is decommissioned in `cleanup`; its inherited lock is irrelevant once it is stopped. Releasing it is out of scope for this plan.
- **Privilege:** `CREATE EVENT TRIGGER` requires superuser; the tool already connects via `PG.SuperuserDSN`.
